# 手机个股分析与云端请求

手机默认使用云端网页和加密快照，不在解锁后自动连接电脑。首页不展示内部做T训练与影子信号面板，历史记录保留在“迭代”的折叠区。

综合预测页支持股票名称或六位代码搜索。选择股票后，独立云端任务读取日线、60分钟、15分钟、5分钟数据，返回结构图、量价与数学观察、结构价位参考及数据缺口。收盘后仍可分析已完成K线。概率尚未验证时不显示伪造的概率或收益区间。

查询任务与交易值守使用不同的工作流、并发组和临时数据库。查询不启动交易引擎、不改账户、不记录模拟成交。合格的概率模型若存在，只读取其JSON系数；账户状态只在内存解密，只有模型表复制到隔离数据库。

## 部署

1. 先通过预测、静态页面、队列和交接测试，将源码与 `aq5-forecast-request.yml` 更新到 main。
2. 保留 Worker 原有 KV、LIVE Durable Object 绑定、定时任务和 SECRET / LIVE_KEY / GH_TOKEN。新增 FORECAST_KEY，值为手机密码经 PBKDF2-HMAC-SHA256 派生的32字节十六进制字符串；salt 为UTF-8 `aq5-forecast-request-v1`，迭代200000次。只通过Secret管理接口写入，不写源码、命令行参数或日志。
3. 发布 Worker，再发布网页资源。FORECAST_KEY 仅可请求单股分析，不能发布实时快照或修改账户；执行端沿用 LIVE_KEY。手机改密码时须同步更新这两个派生密钥及 GitHub 的 AQ5_KEY。
4. 实测手机选股提交、GitHub独立任务启动、加密结果校验和展示；确认本机引擎离线时仍可完成。UI合成测试不代替这一项。

## 请求约束

请求队列在现有 Durable Object 类的独立实例中保存。最多保留一小时、20个任务，限制每分钟3个新任务；相同股票近期任务复用。执行使用租约claim，失效执行不能覆盖新结果。结果仅接受AQ5w1密文，并校验SHA-256、体积和分片完整性。

最新结果质量不合格时，客户端可核验同股票最近最多3份、仍在一小时缓存内的历史密文。只展示曾通过校验的结果，保留其原始时点并明确标为历史分析；当前状态仍为数据不合格，旧概率不作为新预测显示。没有合格历史时保留失败说明。

模型未训练、行情不足、结构未确认、期限不满足是不同状态。数据源故障不会通过放宽复权或交易校验解决。腾讯复权双响应不可用时可尝试东方财富双响应，仍执行原全OHLC校验，并保留失败原因。

供应商偶尔返回超过请求数量的日线时，两侧先按日期各取请求范围内最近320根，再逐根验证。原响应哈希、返回条数和超出窗口的最旧日期会保留；窗口内部及最新日期不一致仍拒绝，不通过任意取交集来隐藏缺口。
